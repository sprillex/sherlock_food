Android Terminal Build Automator

A lightweight, terminal-first bash utility designed to clone Android repositories, automatically repair common local environment discrepancies (like SDK paths and Gradle versions), and generate a custom, one-click update and deployment script for that specific app. This completely bypasses the need for heavy IDEs or graphical app managers.

🚀 Quick Start & Usage

1. Initial Setup

Run the setup script and pass the target GitHub repository URL as the only argument:

# Make the script executable (first time only)
chmod +x clone_android.sh

# Clone and configure the target app
./clone_android.sh https://github.com/username/projectname

2. Updating & Installing the App

Once the setup script finishes, it will generate a dedicated update script inside the cloned project folder.

Whenever you want to pull the latest code, compile a fresh APK, and install it to your connected device, simply run:

# Example: If your project was named "map"
~/AndroidStudioProjects/map/update_map.sh

📖 Detailed Information: How It Works

This tool is split into two phases: the initial environment configuration (clone_android.sh) and the ongoing deployment (update_<project>.sh).

Phase 1: clone_android.sh (The Setup)

When you run the main script, it performs the following automated steps:

  1. Workspace Management: Clones the targeted GitHub repository into your default ~/AndroidStudioProjects directory.
  2. Gradle Version Pinning: Forces the project to use Gradle version 8.7. It modifies gradle-wrapper.properties and ensures the gradlew executable is present and correctly permissioned, preventing build failures due to version mismatches.
  3. SDK Path Configuration: Automatically creates a local.properties file so Gradle knows where your Android SDK lives. It will attempt to copy a known-good configuration from a reference project (foodscan) or fallback to the standard Linux SDK path ($HOME/Android/Sdk).
  4. Git Housekeeping: Uses Git's skip-worktree and .git/info/exclude to hide the local modifications to the Gradle wrapper and SDK paths. This prevents you from accidentally committing these local fixes back to the public repository.
  5. Automation Generation: Dynamically writes the update_<project>.sh script tailored specifically for the app you just cloned.

Phase 2: The Generated update_<project>.sh Script

This customized script lives in the root of your newly cloned project and handles all future maintenance. Every time you run it, it will:

  1. Sync: Run git pull to fetch the latest commits from the developer.
  2. Build: Execute ./gradlew assembleDebug to compile a fresh debug APK.
  3. Archive: Rename the generated APK to include a precise timestamp (e.g., Projectname-B2026-05-01-15-30.apk) and save a copy into a dedicated builds/ directory for version history.
  4. Deploy: Use adb to check for a connected Android device. If a device is found, it automatically installs the newly compiled APK.

Prerequisites

To use these scripts successfully, ensure your terminal environment has the following available:

  • git
  • gradle (System level, for initial wrapper generation)
  • adb (Android Debug Bridge, for installing to your device)
  • Java Development Kit (JDK) compatible with Android builds
